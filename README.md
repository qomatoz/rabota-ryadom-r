# Работа рядом — Кунгур и Пермь

Личный адаптивный сайт для мониторинга вакансий. Интерфейс работает на GitHub Pages, поиск запускается в GitHub Actions по расписанию (примерно раз в 30 минут). Компьютер пользователя может быть выключен.

## Что входит
- Кунгур: вакансии без ограничения по графику.
- Пермь: в выдачу попадают объявления, где в тексте обнаружены признаки суточного/24-часового графика.
- Автопоиск по публичному API HH.ru.
- Избранное хранится локально в браузере устройства.
- Статусы «Подтверждено» и «Нужно уточнить».
- Адаптивный интерфейс для телефона и компьютера.

## Важные ограничения
1. Это бесплатный MVP на публичном репозитории GitHub. GitHub Pages для GitHub Free требует публичный репозиторий; стандартные GitHub-hosted Actions в публичных репозиториях бесплатны. Не помещайте сюда пароли, личные документы или другие секреты.
2. HH.ru — пока единственный подключённый источник. API и доступность данных зависят от правил и ограничений HH.ru. В отдельных случаях API может ограничивать запросы или возвращать ошибки.
3. Автоматический анализ текста не может гарантировать фактические условия работодателя. «Подтверждено» означает только то, что в тексте объявления найдены явные признаки отсутствия оформления и оплаты на руки/после налогов. Перед выходом обязательно уточняйте, что не будет ни ТК РФ, ни ГПХ, ни самозанятости и что платят наличными/на руки.
4. Вакансии с неопределёнными условиями помещаются в «Нужно уточнить», а не выдаются за гарантированно подходящие.
5. HH.ru обычно ориентирован на официальные вакансии. Поэтому количество строгих совпадений может быть небольшим или нулевым. Дополнительные источники (например, площадки объявлений) можно подключить отдельно, соблюдая их правила доступа.
6. Избранное хранится в localStorage конкретного браузера и не синхронизируется между устройствами в этой бесплатной версии.

## Установка — один раз
1. Создайте аккаунт на https://github.com/ (если его ещё нет).
2. Создайте **публичный** репозиторий, например `rabota-ryadom`.
3. Загрузите в него все файлы этого архива, сохранив структуру папок.
4. Откройте **Settings → Pages**. В разделе Build and deployment выберите **Deploy from a branch**, branch `main`, folder `/ (root)`, нажмите Save.
5. Откройте вкладку **Actions**. Если GitHub попросит разрешить запуск workflows, нажмите **I understand my workflows, go ahead and enable them**.
6. Откройте Actions → Search vacancies → Run workflow для первого запуска.
7. После завершения откройте **Settings → Pages** — там появится адрес сайта вида `https://ВАШ-ЛОГИН.github.io/rabota-ryadom/`.

После этого workflow запускается по расписанию дважды в час (на 7-й и 37-й минуте). Запуски GitHub Actions могут задерживаться, поэтому точность расписания не гарантируется.

## Как поменять частоту
В `.github/workflows/search.yml` строка `cron: "7,37 * * * *"` задаёт запуск дважды в час. Не ставьте слишком частые запросы к источнику.

## Запуск вручную на компьютере
```bash
python -m pip install -r requirements.txt
python fetch_vacancies.py
python -m http.server 8000
```
Затем откройте `http://localhost:8000`.

## Условия классификации
Скрипт исключает явные признаки ТК РФ, ГПХ, самозанятости и официального трудоустройства. Статус «Подтверждено» присваивается только если найдено явное указание на работу без оформления и одновременно признак выплаты на руки/после вычета налогов/наличными. Для Перми дополнительно требуется указание на сутки, 24 часа или близкий суточный график.
